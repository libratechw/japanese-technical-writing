# japanese-technical-writing

日本語のテクニカルライティングをまとめたエージェント用スキルです。
実社会で具体的な目的を達するために書く文章を対象とします。
README、説明書、手順書、報告書、調査レポート、指示書、依頼書、提案書、引き継ぎ資料、案内文、Issue や Pull Request の本文。
文学、評論、批評は対象ではありません。

## 何が書いてあるか

文書の目的と、目的から導かれる機能を決めることを最優先します。
その内容が読み手へ伝わるかを、理解の正確さ、理解にかかる時間、ストレスの3指標で評価します。

構成、用語、数値、論証、図表、改行の選び方と、意味を保って推敲するための基準を扱います。
推敲では、説明の過不足や論理の抜けを確認し、不確実性や条件を変えずに不要な反復・演出を省きます。
手順と判断基準の正本は [SKILL.md](SKILL.md) です。

## 使い方

`SKILL.md` は Claude Code、Codex、opencode が共通して読める形式です。
各ツールのスキル探索先へ、このリポジトリを置くか symlink します。

```
~/.claude/skills/japanese-technical-writing/SKILL.md
~/.codex/skills/japanese-technical-writing/SKILL.md
~/.config/opencode/skills/japanese-technical-writing/SKILL.md
```

複数のツールで共有するなら、実体を1か所に置いて各探索先から symlink する方が、
内容がずれません。

## 出典

規則の裏付けにした資料です。文章はすべて書き下ろしで、逐語引用は含みません。
どの規則を支えているかを併記します。

- 文化審議会「公用文作成の考え方」2022年1月7日建議。文・見出し・構成の規則。無償
- 木下是雄『理科系の作文技術』1981。パラグラフ、重点先行主義、事実と意見
- 本多勝一『日本語の作文技術』1976。修飾の順序と読点の原則
- サイボウズ「テクニカルライティングの基本」2023年版（仲田尚央）。段落の長さの目安、能動態と受動態の使い分け、推敲の観点
- Robin Williams『ノンデザイナーズ・デザインブック』。近接、整列、コントラスト、反復
- Richard E. Mayer のマルチメディア学習理論。図と文の重複、対応するものを近くに置く

- [k16shikano「japanese-tech-writing」](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)。論証のつながり、不確実性を保つ推敲、読み手の負荷、不要な演出を点検する観点
- [CommonMark Spec: Hard line breaks](https://spec.commonmark.org/0.31.2/#hard-line-breaks)。Markdown の段落内改行

## 貢献

規則の追加や修正の提案を歓迎します。

このスキルは、実際の文書で起きた失敗を根拠に書いています。
提案には、その規則がない状態でどう失敗したかを添えてください。
現在の規則で防げているなら、追加せずに済みます。
