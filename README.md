# japanese-practical-writing

リポジトリの中で更新され続ける日本語文書の書き方をまとめたエージェント用スキルです。
README、PR 本文、調査報告、仕様書、issue、申し送りを対象とします。

## 何が書いてあるか

わかりやすさを読み手基準の3指標で定義し、それ以外はすべて手段として扱います。

- 正確に理解できた人の割合。高いほど良い
- 理解にかかった時間。短いほど良い
- 読み手が受けたストレス。少ないほど良い

一文一義、修飾の順序、読点の打ち方といった古典的な規範は、既存の資料が詳しく扱っています。
このスキルが書いているのは、それらを知っていてもなお落ちる部分です。

- 想定する読み手を決めてから書く
- 自然に理解できる順番で書く
- 重要度で3つに分け、低いものは本文から出す
- 強調は拾い読みのために付ける
- 同じものは同じ名前で呼び、違うものは違う名前で呼ぶ
- 数値は主張を支えるために置く
- 事実と意見を分け、根拠の範囲を超えない
- 図表は、文章より速く正確に伝わるときに使う

## 使い方

`SKILL.md` は Claude Code、Codex、opencode が共通して読める形式です。
各ツールのスキル探索先へ、このリポジトリを置くか symlink します。

```
~/.claude/skills/japanese-practical-writing/SKILL.md
~/.codex/skills/japanese-practical-writing/SKILL.md
~/.config/opencode/skills/japanese-practical-writing/SKILL.md
```

複数のツールで共有するなら、実体を1か所に置いて各探索先から symlink する方が、
内容がずれません。

- サイボウズ「テクニカルライティングの基本」2023年版（仲田尚央）
- Robin Williams『ノンデザイナーズ・デザインブック』
- Richard E. Mayer のマルチメディア学習理論

## 貢献

規則の追加や修正の提案を歓迎します。

このスキルは、実際の文書で起きた失敗を根拠に書いています。
提案には、その規則がない状態でどう失敗したかを添えてください。
現在の規則で防げているなら、追加せずに済みます。
